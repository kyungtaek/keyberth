# AI Micro 키 매핑과 앱 연동 가이드

AI Micro의 Universal Agent 펌웨어 0.2.18은 번호 키 13개, 노브 회전 2방향, 조이스틱 4방향을 구분한다. **키 매핑 편집**에서 기기의 컨트롤을 선택하고 원하는 동작이나 터미널 단축키를 저장한다. **기본값 복원**은 선택한 컨트롤 한 개의 배정을 되돌린다. 아래 표는 cmux 키맵 기준이다. 키맵 선택기에서 앱별로 번호 키와 방향키를 설정한다.

## 편집할 수 있는 입력

아래 ID는 USB 키보드 스캔 코드가 아니라 Universal Agent의 `AMINPUT` 메시지에 들어 있는 `id` 문자열이다. 각 줄은 사용자가 매핑을 바꾸기 전의 동작이다.

| 실물 컨트롤 | 입력 ID | 기본 cmux 동작 |
| --- | --- | --- |
| 1 | `K01` | 최근 세션 1 선택 |
| 2 | `K02` | 최근 세션 2 선택 |
| 3 | `K03` | 최근 세션 3 선택 |
| 4 | `K04` | 최근 세션 4 선택 |
| 5 | `K05` | 최근 세션 5 선택 |
| 6 | `K06` | 최근 세션 6 선택 |
| 7 | `K07` | 현재 창에 워크스페이스를 만들고 선택 |
| 8 | `K08` | 현재 대화에 대응하는 대기 중인 권한 요청 한 건을 한 번 승인 |
| 9 | `K09` | 현재 대화에 대응하는 대기 중인 권한 요청 한 건을 거부 |
| 10 | `K10` | 현재 워크스페이스의 오른쪽 사이드 패널 열기 |
| 11 | `K11` | 활성 터미널에 스페이스 한 글자 보내기 |
| 12 | `K12` | 선택한 대화를 오른쪽 새 분할에 포크 |
| 13 | `K13` | 활성 터미널에 엔터 보내기 |
| 노브 반시계 | `ENC_CCW` | 이전 앱 키맵 (고정) |
| 노브 시계 | `ENC_CW` | 다음 앱 키맵 (고정) |
| 노브 누름 | `ENC_PRESS` | 전역 자동 전환 켬/끔 (고정) |
| 조이스틱 위 | `JOY_UP` | 같은 워크스페이스에서 위쪽 이웃 패널 선택 |
| 조이스틱 아래 | `JOY_DOWN` | 같은 워크스페이스에서 아래쪽 이웃 패널 선택 |
| 조이스틱 왼쪽 | `JOY_LEFT` | 같은 워크스페이스에서 왼쪽 이웃 패널 선택 |
| 조이스틱 오른쪽 | `JOY_RIGHT` | 같은 워크스페이스에서 오른쪽 이웃 패널 선택 |

최근 세션 목록은 활성 터미널, 최근 선택 기록, 나머지 열린 터미널 순서로 중복을 제거해 여섯 개까지 채운다. 노브는 여섯 앱 키맵을 양방향으로 순환한다. 조이스틱은 지정한 방향에 이웃 패널이 있을 때만 포커스를 옮긴다. [입력 해석과 최근 세션 정렬](../Sources/MicroCore/Deck.swift) · [cmux 명령 실행](../Sources/MicroCompanion/CmuxClient.swift)

## 매핑이 실행되는 방식

물리 입력 하나는 내장 동작 하나 또는 터미널 단축키 하나로 바꿀 수 있다. 편집기에서 7번에 **스페이스**를 배정하면 7번 키에 저장되는 값은 `K07 → K11`이다. 이후 11번에 다른 동작을 배정해도 7번은 스페이스 동작을 그대로 실행한다. 매핑은 물리 입력에서 한 번만 해석한다.

편집기에서 Ctrl 스위치를 켜고 기본 키 A를 선택하면 저장되는 값은 `K07 → ctrl+a`이고, 활성 cmux 터미널이 그 키 조합을 받는다. 조합에는 `cmd`, `ctrl`, `alt`, `shift`와 영문자·숫자 및 `= - [ ]` 기호를 쓸 수 있다. `enter`, `escape`, `space`, `tab`, `up`, `f1` 같은 이름 키도 지원한다. 편집기는 이를 Mac 사용자 설정의 `keymapOverridesV1` 사전에 프로필별로 보관한다. 값이 없는 컨트롤은 기본 배정을 따른다. [매핑 모델 및 편집기](../electron/renderer.js) · [단축키 문법](../Sources/MicroCore/Cmux.swift)

## 다른 앱을 연결할 때

앱 이름, 번들 ID, 순서와 기본 배정은 [AppProfile](../Sources/MicroCore/AppProfile.swift)에 있다. cmux는 전용 CLI 클라이언트를 사용한다. 나머지 앱은 [DesktopShortcut](../Sources/MicroCompanion/DesktopShortcut.swift)이 대상 프로세스에 키 조합을 보낸다. cmux 배정은 기존 `physicalKeyMappings`, 다른 앱의 변경값은 `desktopKeyMaps` 아래 해당 프로필에 저장한다. 번호 키나 방향키에 배정할 수 있는 cmux 동작에는 이전·다음 세션도 포함된다.

| 연결할 부분 | 현재 구현 | 문서 편집기 예시 |
| --- | --- | --- |
| 입력 수신과 매핑 | `AgentHID`가 현재 USB 세션과 이벤트 순번을 확인하고 `pressed == true`인 입력을 `DeckInput`으로 변환한다. `Companion.handle`이 사용자 배정을 해석한다. | USB 연결과 키 편집기를 재사용한다. 해석한 동작을 새 편집기 클라이언트에 전달한다. |
| 대상 목록과 선택 | `Companion.refresh`가 열린 터미널과 최근 기록으로 슬롯을 만들고, 슬롯 선택 시 창·워크스페이스·표면 ID를 확인해 포커스를 옮긴다. | 앱이 제공하는 문서 ID와 창 ID로 슬롯을 구성한다. 제목이 같은 문서도 ID로 구분하고, 대상 창을 전면에 올린 뒤 문서를 선택한다. |
| 동작 실행 | `Companion.drain`이 입력을 순서대로 처리하고 `CmuxClient`가 단축키 전송, 패널 이동, 승인, 포크를 실행한다. | 번호 키는 이전·다음 문서, 방향키는 인접 편집 그룹으로 연결할 수 있다. 편집기 명령 API나 CLI가 지원하는 동작을 명시적으로 선택한다. |
| 대상 고유 기능 | cmux의 승인·거부는 해당 대화에 속한 대기 요청이 한 건일 때 실행한다. Codex 포크는 패널이 실제로 쓰는 대화 ID를 확인한다. | 승인 API나 포크 개념이 없으면 해당 동작을 사용할 수 없음으로 표시한다. 전역 엔터 키로 승인 동작을 흉내 내면 다른 문서나 대화상자가 입력을 받을 수 있다. |
| 상태와 LED | `SessionLight` 배열 여섯 칸과 선택 위치를 `AgentHID.display`에 전달한다. | 문서별 빌드나 작업 상태가 있다면 같은 상태 모델로 변환한다. 닫힌 문서가 있으면 최신 목록으로 슬롯과 LED를 함께 갱신한다. |

새 앱의 동작 이름과 기존 숫자 ID를 분리해 두면 같은 키에 앱별 의미를 부여하기 쉽다. 포커스 자동 전환은 전역 설정 하나를 사용한다. [입력 큐·최근 세션·LED 갱신](../Sources/MicroCompanion/MicroCompanion.swift) · [Codex 대화 ID 확인](../Sources/MicroCompanion/CodexBinding.swift)

## LED 출력과 검증

USB 전송은 같은 기기 위치의 HID usage page `0xFF31`, usage `1`, report ID `7`을 사용한다. `AMFRAME`은 1~6번 슬롯 순서의 상태 코드 여섯 자리이고, `AMSELECT`는 선택 슬롯 번호(없으면 0)다. 코드 `0`은 빈 슬롯·상태 미확인, `1`은 대기·활성, `2`는 실행 중, `3`은 입력 대기, `4`는 완료를 뜻한다. Universal Agent 0.2.18 실기기의 선택 슬롯에서 대기는 흰색, 실행 중은 파란색, 입력 대기는 붉은색, 완료는 초록색 점멸로 관찰됐다. 1~6번 키를 재배정해도 LED는 최근 세션의 슬롯 위치를 계속 표시한다. [USB 세션과 출력](../Sources/MicroCompanion/AgentDevice.swift) · [상태 코드](../Sources/MicroCore/Cmux.swift)

1. `swift test`로 입력 ID 변환과 최근 세션 순서를 검사한다. 새 앱의 실행 코드는 별도로 테스트해 목표 문서·창 ID가 정확한지 확인한다.
2. 재배정한 물리 키를 한 번 눌렀다 뗀다. 동작이 한 번 발생하고, 수신 앱의 대상 ID가 편집기에서 의도한 대상과 일치하는지 확인한다.
3. 다른 앱을 전면에 둔 뒤 세션 키를 누른다. 전면 앱과 활성 문서를 모두 확인한다. cmux 터미널에서는 스페이스와 엔터가 각각 바이트 `0x20`, `0x0D`로 도착하는지도 확인할 수 있다.
4. 실행 중 → 입력 대기 → 완료 상태를 만들어 각 전환의 슬롯 번호, 전송 응답, 실기기의 색을 함께 확인한다. 포크를 지원하는 앱은 자식에서 다시 포크하고, 손자의 부모 ID가 직전 자식 ID와 같은지 확인한다.

## 기기 설정

Keyberth 창 상단의 **기기 설정**에서 자동 절전(끔 또는 1~120분)과 부저 볼륨(0~100%)을 변경한다. USB로 현재 값을 읽고 저장 후 다시 읽어 확인한다. 부저 자체가 꺼져 있으면 볼륨을 바꿔도 소리가 나지 않는다.

## 앱 키맵 관리

기기 설정에서 내장 프로필 또는 응용 프로그램을 추가한다. 키맵을 삭제하면 해당 키 배정도 삭제된다. Slack과 Obsidian 전용 프로필은 등록 목록에서 제외했다.

## Codex와 Claude

AI Micro 0.2.96의 macOS 기본 키표를 기준으로 한다. 노브는 모든 프로필에서 키맵 순회와 자동 전환에 사용한다.

| 입력 | Codex Desktop | Claude Desktop | Claude Code 세션 |
|---|---|---|---|
| 1 / 2 | 최근 세션 1 / 2 | 사이드바 / 전체 화면 | 최근 세션 1 / 2 |
| 3 / 4 | 최근 세션 3 / 4 | 글자 확대 / 축소 | 최근 세션 3 / 4 |
| 5 / 6 | 최근 세션 5 / 6 | 이전 / 다음 대화 | 최근 세션 5 / 6 |
| 7 | ChatGPT Dots 탭 | Escape | Escape |
| 8 / 9 | 승인 / 거부 | 전체 선택 / Backspace | 전체 선택 / Backspace |
| 10 | 대화 포크 | 실행 취소 | 실행 취소 |
| 11 | 작성창 받아쓰기 (누르고 말하기) | ⌘D | ⌘D |
| 12 / 13 | 새 대화 / 보내기 | 새 대화 / Enter | 새 대화 / Enter |
| 방향키 | 위 계획 모드 · 아래 사이드바 · 좌우 방문 기록 | 상하좌우 | 상하좌우 |

Claude Code 세션 내역은 Claude Desktop에 등록된 로컬 세션의 메타데이터에서 읽는다. **기기 설정 → Claude Code 세션 훅 → 연결**을 선택한 뒤 새 Claude Code 세션을 시작한다. 승인과 거절은 **키 매핑 → 기능 → 대화 제어**에서 배정한다. 선택한 세션의 권한 요청이 한 건이면 그 요청에 답한다. 여러 건이면 **최근 세션 → Claude Code 슬롯 설정**에서 원하는 요청을 선택한다. 같은 화면에서 세션 소스를 고르고 각 슬롯을 특정 세션에 고정하거나 최근 활동순으로 되돌릴 수 있다. 훅은 Keyberth가 담당하는 항목만 추가·제거한다.

**cmux 11번**을 짧게 누르면 공백 한 글자를 입력한다. 길게 누르면 같은 터미널에 공백을 반복하고 손을 떼면 멈춘다. Claude Code CLI에서 기본 Space 바인딩과 `/voice hold`가 활성화되어 있어야 받아쓰기로 동작한다. 터미널의 마이크 권한은 Claude Code가 요청한다. [Claude Code 음성 입력 문서](https://code.claude.com/docs/en/voice-dictation)

**키 매핑 → 단축키**에서 ⌘ Command, ⌃ Control, ⌥ Option, ⇧ Shift를 함께 선택할 수 있다. cmux에서 Command가 포함된 조합은 macOS 키 이벤트로 cmux 앱에 전달한다.

**기기 설정 → 키맵 파일**에서 JSON을 가져오거나 내보낸다. 다음 파일은 cmux의 7번을 ⌘⌃K로 설정하고 이 프로필의 다른 키를 기본값으로 복원한다. 파일에 생략한 프로필은 기존 값을 유지한다. 내보내기에는 기본값과 다른 키, Claude Code 소스와 슬롯 고정 정보가 저장된다.

```json
{"version":1,"profiles":{"cmux":{"K07":"cmd+ctrl+k"}}}
```

## 세션 조명

기본 슬롯은 유휴 흰색, 실행 중 파랑, 주의 요청 주황, 아직 열지 않은 새 완료 초록으로 표시한다. 처음 발견한 과거 완료는 유휴로 표시한다.

기기 설정 → 세션 조명에서 상태를 고른 뒤 슬롯 LED와 바닥 조명의 색상·애니메이션을 각각 선택하고 **조명 저장**을 누른다. 설정은 이 Mac에 저장되며 USB 연결이 복구되면 다시 적용된다. 사용자 설정이 없으면 슬롯 기본색을 적용하며 바닥 조명은 기기 설정을 따른다.

Codex 실행 슬롯의 기본 파란색 숨쉬기는 펌웨어가 직접 그린다. 여러 슬롯이 실행 중이면 현재 보고 있는 실행 슬롯을, 그 슬롯을 확인할 수 없으면 번호가 가장 낮은 실행 슬롯을 강조한다. 다른 실행 슬롯은 파란색을 유지한다.

바닥 조명은 기기 전체가 공유한다. 선택된 세션이 있으면 그 상태를, 선택이 없으면 입력 요청 → 실행 중 → 완료 → 활성 → 대기 → 상태 미확인 → 빈 슬롯 순으로 표시한다. 무지개 효과에서는 펌웨어가 색상을 순환시킨다.

Universal Agent 0.2.18에서 입력·세션 연결은 report 7을 사용하고 사용자 조명은 같은 USB 위치의 report 6으로 보낸다. 슬롯 6개는 `v.oai.thstatus`, 바닥 조명은 `v.oai.rgbcfg`의 `ambient`로 보낸다. 두 요청 모두 일치하는 성공 응답을 받으면 앱이 수신 상태를 표시한다.

7번은 최근 여섯 슬롯 밖의 대기도 포함한다. 8·9번은 현재 대화에서 대상이 한 건일 때만 처리한다. 정리된 세션은 LED가 꺼진다. 11번을 누르면 시스템 받아쓰기를 시작하고 손을 떼면 종료한다. 받아쓴 문장은 입력란에 남으며 13번으로 보낸다. 11번을 쓰려면 macOS 시스템 설정 → 키보드에서 받아쓰기를 켠다. 13번은 T3 작성창의 보내기 버튼을 실행하며, 실행 중인 대화에서는 T3가 표시하는 대기열 추가 또는 진행 중 메시지 전달 동작을 따른다.
