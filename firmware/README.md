# 키버스-펌웨어

AI Micro ESP32-S3용 개발 버전은 `0.4.5-keyberth`다. 펌웨어 버전은 앱과 독립적으로 `VERSION`에서 관리한다. 제조사가 MIT로 공개한 AI Micro Basic 0.1.0에서 보드 드라이버, HID/CDC와 ROM 복구 경로를 가져왔다. 원본 소스 ZIP의 SHA-256은 `fe5c2d523e76d482c63703adec0264ea1f6a7143add33bd7a3f2ad49854d825b`다. Universal Agent 0.2.18의 USB 동작을 호환 기준으로 삼았다. [제조사 소스 배포본](https://micro.diyshare.cn/downloads/ai-micro-basic/0.1.0/ai-micro-basic-0.1.0-source.zip) · [라이선스](LICENSE)

## 빌드와 연결

ESP-IDF 5.5.4의 ESP32-S3 개발 환경을 활성화하고 이 폴더에서 `idf.py -DIDF_TARGET=esp32s3 build`를 실행한다. 시험 대상은 애플리케이션 이미지 `build/keyberth.bin`이다. 실기기에서 시험하기 전에는 아래 복구 조건을 확인한다.

USB VID/PID는 303A:8360이다. CDC의 `UPDATE_INFO`와 report 7의 `AMHELLO`가 같은 개발 버전을 반환한다. 기존 배포 앱은 펌웨어 버전을 제한하므로 이 저장소의 개발 앱과 함께 시험한다. 개발 앱은 공식 0.2.18도 기존 경로로 처리한다.

| 인터페이스 | 개발 펌웨어의 동작 |
|---|---|
| HID report 7 · FF31/1 | Keyberth의 세션 토큰, 순번, 하트비트, 6개 슬롯 상태, 슬롯 선택, 키 누름·해제, 노브와 방향키 |
| HID report 6 · FF00/1 | Basic의 버전·상태·조명 RPC. Keyberth가 제어권을 가진 동안에는 report 7의 조명을 표시한다. |
| CDC | 상태와 버전 조회, 1200 baud ROM 다운로드 진입 |
| Bluetooth | USB 우선 사용. 배터리에서는 선택된 채널의 HID 서비스를 광고한다. 채널별 페어링 기록은 정품과 별도로 저장한다. |
| 절전·부저 | USB에서 `PREFS_GET`·`PREFS_SET`으로 읽고 저장한다. USB 연결·충전·충전 완료 상태에서는 자동 깊은 절전을 보류한다. 배터리 절전에서 노브 누름이나 전원 버튼으로 깨어난다. 전원 버튼을 두 번 누르면 부저 사용 여부가 바뀐다. |

## 무선 연결과 절전

Mac의 Bluetooth 설정에서 **AI Micro**를 선택해 처음 한 번 페어링한다. Keyberth는 USB를 뽑으면 무선 HID로 다시 연결하고, USB를 연결하면 유선 입력을 우선한다. 정품에 등록된 Mac도 개발 펌웨어에서는 처음에 페어링이 필요하다.

0.4.5에서 1번은 기존 Bluetooth 주소를 유지합니다. 2·3번은 각각 새 주소와 독립 페어링 저장소를 사용하므로 처음 한 번 ‘AI Micro 2’ 또는 ‘AI Micro 3’으로 등록합니다.

터치 버튼을 약 3초 누른 뒤 떼면 채널 선택이 시작된다. 짧게 터치할 때마다 1 → 2 → 3 순으로 바뀌고 약 5초 뒤 확정된다. 선택 중 같은 버튼을 다시 길게 누르면 선택한 채널의 페어링을 지운다. Mac에도 이전 등록이 남아 있다면 해당 기기를 지운 뒤 다시 페어링한다.

배터리에서 자동 절전에 들어간 뒤 노브 또는 전원 버튼을 짧게 누르면 깨어난다. 자동 절전 시간을 0분으로 지정하면 자동 절전이 꺼진다. 기기 설정의 부저 볼륨은 0~100%이며 전원 버튼을 빠르게 두 번 눌러 음소거를 전환한다.

0.4.5 설치 관리자는 정품 파티션 표를 검증한 뒤 두 OTA 슬롯을 검사한다. 기존 제조사 이미지가 있는 슬롯은 보존하고, 비어 있거나 알려진 키버스 이미지가 있는 슬롯을 선택한다. 두 슬롯 모두 다른 데이터가 있으면 쓰기 전에 중단한다.

## 기기 조명 설정 (0.4.0 이상)

USB 설정의 `brightness`는 모든 키캡과 바닥 픽셀에 적용하는 0~100% 전체 밝기다. `styles` 배열은 바닥, 키 1~13 순으로 14개다. 빈 문자열은 자동 조명이고 직접 설정은 RGB 6자리, 효과 1자리(0~6), 밝기와 속도 각 2자리(16진수 00~64)다. 예를 들어 `00ff0046432`는 초록 숨쉬기, 밝기 100%, 속도 50%다. 두 필드는 선택적이며 이전 설정 쓰기 요청은 기존 조명을 보존한다. 앱은 설정 리비전을 확인하고 저장 후 재조회한다. 세 개의 Bluetooth 채널 표시등은 별도 상태 표시등이다.

## 조명 프로토콜

`AMHELLO`의 `keyberth-light-v1` capability를 확인하고 `AMMODE generic`, `AMKEYMODE sessions`를 완료한다. `KBLED`는 기존 report 7 프레이밍과 세션 순번을 사용한다. 탭으로 구분한 명령 구조는 아래와 같다.

```text
KBLED<TAB>세션토큰<TAB>순번<TAB>대상:RRGGBB:효과:밝기:속도
```

대상 1~13은 키캡에 쓰인 번호이고, 0은 8개 픽셀로 이루어진 바닥 전체다. 효과는 소등(0), 고정(1), 스네이크(2), 무지개(3), 숨쉬기(4), 그라데이션(5), 얕은 숨쉬기(6)다. 스네이크가 공간을 따라 이동하는 대상은 바닥이다. 밝기와 속도의 범위는 각각 0~100이다. 잘못된 값은 기존 상태를 유지하고 오류를 반환한다.

- `13:00FF00:4:55:50`은 13번만 초록으로 숨쉬게 한다. `13:000000:0:0:0`은 해당 키를 끈다.
- `0:268AFF:2:40:60`은 바닥에 파란색 스네이크를 그린다. 앞에서 설정한 13번 효과와 동시에 동작한다.
- `AMFRAME`은 세션 상태에 맞춰 1~6번의 기본 스타일을 갱신한다. 이후 호스트는 사용자 지정 스타일을 보낼 수 있다. 7~13번과 바닥의 설정은 각각 다음 명령까지 유지된다. 애니메이션은 기기에서 렌더링한다.
- USB 연결 종료, 세션 종료 또는 4초간 하트비트 단절 시 해당 세션의 스타일을 해제한다. 전송 가능 여부는 호스트가 판별해 보내야 한다.

## 첫 실기기 시험과 복구

1. 현재 실행 파티션이 정품 `factory`이고 버전이 0.2.18인지 확인한다. 기기 식별값, 플래시 크기, 보안 부팅·플래시 암호화·다운로드 모드 제한 여부를 **로컬에서** 기록한다. 잠금 상태의 개발 기기에 이 unsigned 이미지를 올리지 않는다.
2. 앱의 1200 baud 재시작과 별도로 **앱이 전혀 부팅하지 않을 때도 쓸 수 있는 물리적 ROM 다운로드 진입 방법**을 해당 보드에서 검증한다. ROM에서 ESP32-S3와 동일 기기 식별값을 읽고, 쓰기 없이 원본으로 재부팅할 수 있어야 한다.
3. ROM에서 전체 플래시 16 MiB를 두 번 독립적으로 읽어 개인 보관소에 둔다. 페어링 정보가 포함될 수 있다. `python3 tools/verify_backup.py 첫번째.bin 두번째.bin`으로 두 파일, 정품 부트로더·파티션 표·factory 이미지의 해시를 확인한다. 이 검사는 실제 복원 성공과 별개다.
4. 첫 쓰기는 별도 승인 후 현재 사용되지 않는 OTA 앱 파티션에만 한정한다. 실제 파티션 표와 기존 부팅 선택을 읽고 대상 범위와 원본 보존을 확인한다. 이미지의 실제 기록 및 재읽기 검증이 완료된 다음 한 번의 시험 부팅을 선택한다. Basic 배포본의 전체 설치 도구, `idf.py flash`, 전체 지우기를 사용하면 이 보존 조건을 만족하지 못한다.
5. 키버스는 부팅 시 실행 중인 OTA 슬롯과 다음 부팅 슬롯의 일치 여부, 정품 이미지의 SHA-256을 확인한다. 평소 재시작·전원 재인가·절전 해제·채널 전환은 같은 슬롯을 사용한다. 앱에서 **정품으로 복귀**를 선택하면 정품 이미지를 검증하고 factory를 기본으로 지정한 뒤 재부팅한다. 설치 관리자가 같은 기기의 정품 버전과 실행 파티션을 확인한다.
6. 다음 부팅을 지정하기 전의 실패는 별도로 복구해야 한다. 물리적 ROM에서 같은 기기인지 재확인하고, 보존된 factory와 파티션 표가 일치하면 백업한 원래 부팅 선택 데이터를 복원한다. 그 밖의 손상은 동일 기기의 검증된 전체 백업과 실제 차이를 먼저 확인한다. 복구 후 정품 버전, Keyberth 연결, 키 입력, 기존 설정까지 확인해야 복원 검증이 끝난다.

이 기기에서 USB를 통한 ROM 진입, 이중 백업 검증, 정품 파티션 복귀를 확인했다. 앱이 부팅되지 않을 때 사용할 독립적인 물리 ROM 진입 방법은 미확인이다. 개발 빌드는 Keyberth의 **기기 설정 → 펌웨어**에서 설치하거나 롤백한다. Mac 본체와 데이터 전송이 가능한 케이블로 연결한다.
